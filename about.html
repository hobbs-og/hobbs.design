How I work

Most teams I join already have a product, a backlog and a disagreement about what matters. I help them settle it.

Then I build the answer into the system, so the team doesn't have to settle it again. I care how a product feels as much as how it works, and I check that it holds up after it ships.

What that means in practice

Design systems that hold up under pressure

At Bullhorn, 889 of 903 component tokens point at a name instead of a number. Five developers build from it without asking me.

Build accessibility in from the start

Focus and disabled states go into every component from the first draft. In my own system, a contrast failure fails the build.

Find the real problem

At McGraw Hill the content was all there. Teachers couldn't see where it lived, so the work was navigation.

Let the constraints shape the work

Union Home Mortgage had backend engineers and no designer in the room, so I built components they could implement without one.

Say what isn't finished

Fourteen Bullhorn tokens still hold raw values. The case study says so, because I'd rather name a gap than have someone find it.

Know how it gets built

I work in HTML, CSS, SCSS, and enough JavaScript to build the real thing. This site, its token pipeline, and its component library are mine, and the source is public (opens in a new tab).
