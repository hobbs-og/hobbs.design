Union Home Mort­gage

A backend-heavy team was shipping fast with no design system behind it.

Union Home Mortgage was building a set of internal applications to replace parts of a larger, more complex lending platform. Each tool was being built on its own, and they shared very little structure. As the number of applications grew, so did the gaps between them.

No two applications looked or worked the same way.

Layout, hierarchy and interaction changed from one application to the next. The team was mostly backend engineers, and usability and presentation weren't their focus. Users paid for that with extra effort on every screen.

Without a shared structure, every decision started from scratch. The applications got harder to build and harder to use.

The work focused on creating a system the team could actually use.

The goal was a shared foundation, so the UI matched across tools and each new application started with most decisions already made.

That meant building components atomic enough for a backend-heavy team to implement without a designer in the room, and locking down type, color, and grid so nobody had to make those decisions twice.

The system had to fit how the team already built software.

I built a UI kit and design system around how the team already worked. The components were reusable and the patterns were simple to implement.

The team was mostly backend engineers, so every component had to be clear enough to build from the written guidance alone.

Atomic design principles

Interfaces broken down into small components the team could reuse anywhere.

Grid system

One grid for every application, so layouts lined up from tool to tool.

Typography

A grotesk sans-serif picked for legibility, with a clear hierarchy for data-heavy screens.

Color palette

A shared color scale from the brand's primary and secondary colors, checked automatically against the WCAG 2.0 4.5:1 contrast ratio.

Shared components made the applications easier to build and to use.

With shared components, nobody had to rebuild the same pattern for each application.

Layouts and hierarchy became predictable, so screens were easier to scan. Tools that used to feel unrelated now felt like one product.

The team moved faster, and the tools got easier to use.

New applications came together faster, and they matched the rest.

Internal users found the tools easier to navigate, and each new tool took the team less effort to design and build.

A shared foundation meant nobody had to make the same decision twice.
